# GAP LIST — concrete blockers to GA

Ranked by severity:

## 🟥 Hard blockers (must fix before real users)

**G1 — Pool not used for OUTBOUND sends**
- File: `apps/functions/src/sendblue/sendblue-client.ts` + every `sendImessage` caller
- Problem: client-side public page picks a pool number; server-side replies use `SENDBLUE_FROM_NUMBER` env (fixed). Candidate's first SMS lands on one pool number, but ALL subsequent inbound from us comes from the env number. Breaks thread continuity claim.
- Fix shape: `sendImessage` accepts optional `userId` → calls `loadSendbluePool(db)` → `pickFromNumber(pool, userId)` → overrides `from_number` in Sendblue REST call.
- Impact: every PII/Level 1/job-rec SMS goes from wrong number for ~half of candidates.

**G2 — ATS invite reply does not virtualize `_Job` trigger** (REQ ATSADAPTER-09)
- File: `apps/functions/src/sendblue/webhook.ts` or `triggers/`
- Problem: Pattern B candidate gets invite SMS "Reply START". Current pipeline does nothing special with "START" — no trigger fires.
- Fix shape: after `paAtsInboundWebhook` fires the invite, stamp `pa-ats-pending-trigger/{phoneE164}` doc with `{jobId, userId, expiresAt}`. Inbound webhook checks this BEFORE Claire and synthesizes the `_Job` trigger context.
- Impact: Pattern B broken end-to-end. Manual workaround: candidate types full `WeKruit_<jobId>_<userId>_Job` trigger.

**G3 — ATS Handshake HMAC secret is placeholder**
- Secret Manager: `ATS_HANDSHAKE_HMAC_SECRET = "placeholder_change_in_production_..."`
- Problem: any HMAC test from real Handshake will fail (401)
- Fix: `firebase functions:secrets:set ATS_HANDSHAKE_HMAC_SECRET` with real Handshake-issued secret
- Impact: Pattern B production traffic = 0% reach until rotated. Adam-only action.

## 🟧 Soft blockers (fix soon or document workaround)

**G4 — `pa-prescreen-pending-invites` write path silently fails**
- File: `apps/dashboard-web/src/pages/PublicJob.tsx`
- Problem: client tries to write requestedUserId stub doc but Firestore rule is operator-only. Catch swallows. Server-side resolution on first inbound is documented but NOT implemented.
- Fix shape: either (a) loosen rule to allow create+single-write on this collection by anyone for pending invites, OR (b) add server resolution lookup in webhook before user-create. Currently a fresh inbound creates a new pa-users by phone with no link back to requestedUserId.
- Impact: marketing analytics broken — can't attribute trigger back to specific job-page visit. Functional flow still works.

**G5 — Match cascade does NOT read new Level 1 tags (`minSalaryUsd`, `companySize`, `industrySector`)**
- File: `apps/job-rec/src/v16/score.ts` (or wherever `queryMatchingJobsV16` filters)
- Problem: we write these fields to `pa-users.tags` but v16 cascade only reads `yoeRange`, `visaStatus`, `targetLocations` from this set. New fields don't influence ranking.
- Fix shape: extend v16 hard filter (drop jobs paying < `minSalaryUsd`) and soft-score weight (`companySize`/`industrySector` overlap with target). Update spec D8.
- Impact: Adam asks "candidate said scale-up only" → still gets enterprise jobs in recs.

**G6 — `PA_CV_INGEST_URL` env not verified on deployed CF**
- File: `apps/functions/src/ats-inbound-webhook.ts:96` reads `process.env.PA_CV_INGEST_URL`
- Problem: resume bind no-ops silently when env unset; current deploy state unverified
- Fix: check Firebase Functions runtime env, set if missing
- Impact: Pattern B candidates whose resume came via ATS webhook get NO resume parsing → match cascade falls back to chat-only tags.

**G7 — Simulator covers prescreen only, not PII + Level 1 chain**
- File: `scripts/v19-simulate-prescreen.mjs`
- Problem: ends at PASS terminal; doesn't replay PII Q1-Q3 + Level 1 Q1-Q6
- Fix shape: extend simulator to chain into `PiiConfirmPipeline` w/ canned 9 answers, assert all writes
- Impact: can't catch Level 1 regressions without manual SMS test. Live verification is the only safety net right now.
