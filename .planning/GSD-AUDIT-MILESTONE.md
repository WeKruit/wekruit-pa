# GSD milestone audit (`$gsd-audit-milestone`)

**Purpose:** Confirm a milestone hit its **definition of done** before archive/closure: aggregate phase verifications, cross-reference requirements, run cross-phase integration/E2E reasoning, and write a single milestone audit artifact.

## Where the workflow lives (orchestrator source)

On a machine with the Codex **get-shit-done** (GSD) toolchain installed:

- **Workflow:** `~/.codex/get-shit-done/workflows/audit-milestone.md`
- **Tooling:** `node "$HOME/.codex/get-shit-done/bin/gsd-tools.cjs"` (`init milestone-op`, `phases list`, `find-phase`, `summary-extract`, `config-get workflow.nyquist_validation`, etc.)
- **Skill (Cursor / Codex):** invoke **`$gsd-audit-milestone`** — maps to the same process (see user skill `gsd-audit-milestone`).

Sessions without that install can still follow the **logical checklist** in this file and produce `v*-MILESTONE-AUDIT.md` manually.

## What the orchestrator does (summary)

1. **Scope** — Milestone version from args or `.planning/ROADMAP.md` / `STATE.md`; list phase directories in scope.
2. **Phase verification** — For each phase, read `*-VERIFICATION.md`. Missing file → **blocker** (“unverified phase”).
3. **Integration** — Spawn **`gsd-integration-checker`** with milestone REQ-IDs and phase exports; map findings to REQ-IDs.
4. **Requirements (3-source)** — Cross-check:
   - `.planning/REQUIREMENTS.md` traceability table
   - Each phase `VERIFICATION.md` requirements table
   - Each phase `*-SUMMARY.md` YAML `requirements-completed`
5. **Orphans** — REQ-IDs in traceability but absent from **all** phase VERIFICATION → treat as unsatisfied.
6. **Nyquist (optional)** — If `workflow.nyquist_validation` not `false`, scan `*-VALIDATION.md` per phase.
7. **Output** — `.planning/v{version}-MILESTONE-AUDIT.md` with YAML frontmatter (`status: passed | gaps_found | tech_debt`) + narrative.

## When to run (for future sessions)

- Before **`$gsd-complete-milestone`** or archiving a version’s phase folders.
- After large cross-cutting ships (onboarding, orchestrator, matching, safety).
- When promoting a new “current milestone” in `STATE.md` — ensure the **outgoing** milestone has an audit file.

## Production invariants to sanity-check during E2E/integration

These are **not** generated by GSD automatically; integration review should still confirm:

- **`__PA_RESET__`** (and synonyms) — gated only by **`PA_ADMIN_USER_IDS`** on Cloud Functions (`maybeHandleResetCommand`); `pa_users.testMode` does **not** authorize reset.
- **`__PA_FIND_MATCH__`** — same allowlist pattern in Sendblue webhook.
- **Deploy / verify contract** — root `CLAUDE.md` (functions deploy, scenario runner, long-context where applicable).
