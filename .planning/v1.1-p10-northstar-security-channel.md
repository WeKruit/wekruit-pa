## 3. Security 视角：Prompt injection 与 OpenAI SDK

**事实（与「SDK 里有没有现成反注入」相关）：**

- **OpenAI Agents SDK / Responses** 不替你挡用户 jailbreak 或 prompt injection。模型仍会把用户文本当对话的一部分；**没有**「打开即防注入」的一键开关。
- ** Moderation API** 是**独立**能力（内容政策类别），可放在编排前后作可选门；**不是**针对「忽略上文」类注入的专防，且与求职 IM 的误伤需调参。
- 你们已具备的**工程防线**（代码库内）应持续强化，而不是寄望 SDK：
  - **工具面：** `agent.toolPolicy === "allowlist"` + `canUseConnector` + 每轮 budget（`packages/pa-safety` + `buildTurnTools` / `runConnector`）。注入链 **最难变成「任意工具」** 的靠的是 **allowlist + budget**，不是 system prompt 一句话。
  - **记忆面：** `filterMemoryWrite` / `isUnsafeMemoryContent` 防明显敏感与注入样本文写入（`pa-safety` + `pa-connectors` 引用）。
  - **输入面：** `checkPromptInjection`（`INJECTION_PATTERNS` 正则）在 **`pa-safety` 内实现**。

**缺口（P10 要盯的）：**

- 需**核实 / 补线**：`checkPromptInjection` 与 `enforceRateLimit` 是否在 **每条** `processInboundEvent` / broker 入队前被调用，并在拒绝时写 **`pa_audit_events` / 未来 `pa_abuse_events`（Phase 23）**。若仅存在于 `pa-safety` 单测而**未挂 orchestrator/CF**，则属于 **「库有了、枪没上膛」**。
- **regex 覆盖有限**：多语言、变体、拆字绕过会持续存在；**缓解** = 金线用例 `eval-prompt-injection-in-fact-zh.yaml` + 定期 red-team，而不是指望一层正则收尾。
- **输出侧**：Voice / normalizer 解决的是「像人 + 不泄漏格式」；**不**等价于对模型被劫持后的**出站内容**做策略过滤——若需与 Moderation 对齐，应单独产品决策（成本 + 误杀）。

**结论可写进架构主张：** 安全是 **产品策略层（allowlist、预算、记忆门、频控、审计）+ 运营层（beta 名单、Phase 23 滥用面）**；**不是**「OpenAI 某个 flag」。

## 4. 通道架构：Sendblue 与 macOS 统一进「大脑」

**你的判断对：** 两条通道应 **只换「怎么进 / 怎么出」**，**不换** `agent runtime + orchestrator` 的语义。

建议在心里固定一张图：

```text
[ Channel A: macOS worker ]  --poll/chat.db-->  (normalize)  --broker-->
[ Channel B: Sendblue ]      --webhook HMAC-->   (normalize)  --broker-->
                                                          |
                                                          v
                                            pa_inbound_events (统一 idempotency 键策略各通道一条)
                                                          |
                                                          v
                                            orchestrator → Agents SDK (同一套 agent 定义)
                                                          |
                    pa_messages / pa_outbound  <----------+
                                        |
         Channel A: worker 读 outbox 发本地 iMessage
         Channel B: CF onCreate(pa_outbound) -> Sendblue REST
```

- **可复用：** `claimAndProcessInboundEvent`、turn、memory、tool bridge、`normalizeForIMessage`（在 orchestrator 出口，两通道一致）。
- **只不同：**
  - Inbound：rowId vs `message_handle`；HMAC 仅 B。
  - Outbound：Photon SDK / AppleScript vs `api.sendblue.co` REST。
- **禁止：** 在 Sendblue 里再开一套「第二套 agent 配置」作为默认路径；若要有 A/B，应用 **同一代码路径 + 特性开关**，而不是复制 orchestrator。
