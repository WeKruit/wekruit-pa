## 2. 北极星与范围

**北极星：** 求职场景下、**像真人朋友一样靠谱** 的 PA：记忆 + 工具 + 合规边界 + **不泄漏 markdown 的 iMessage 级纯文本**；closed beta **≤20 人**；不依赖换大模型，而依赖 **Bible + prompt 结构 + eval + 出站 normalizer**。

**本里程碑 v1.1 必须交付（Build scope）：**

- **P0-Brain:** Phase **18** Companion Voice v1、Phase **20** Output Normalizer、**Bible** 已锁于 [`phases/18-companion-voice-v1/CHARACTER-BIBLE-v1.md`](./phases/18-companion-voice-v1/CHARACTER-BIBLE-v1.md)。  
- **P0-Channel:** Phase **21** Sendblue 集成，与 macOS 通过 **`PA_CHANNEL_LEGACY`** 可切换；**不**复制第二套 orchestrator。  
- **P0-Safety:** 入站路径 **显式** 接入 `packages/pa-safety` 的 `checkPromptInjection` + `enforceRateLimit`（见 §7）；拒绝时写 `pa_audit_events`；为 Phase 23 的 `pa_abuse_events` 产线留一致语义。  
- **P0-QA:** Persona + Normalizer 的 **分层 QA** + 可选 **LLM 多轮对话模拟**（§5–§6）。  
- **P1（与 v1.1 同仓规划、可紧接 18/20 后并行）：** Phase **19** Mirror、**22** Proactive、**23** Closed beta 滥用面；未列入「本文件第一截断必须全绿」的，以 [`.planning/ROADMAP.md`](./ROADMAP.md) 为准。

## 6. LLM↔LLM 多轮（不经 iMessage）

**目标：** 在 **真 orchestrator + 默认 agent** 上跑多轮，直接肉眼看 **对话质量**，无需 chat.db / 真发 iMessage。

**机制：**

- 现有 [`tests/scenarios/runner.mjs`](../tests/scenarios/runner.mjs) 已写 `pa_inbound_events`，与产线同构。  
- 增加 **用户模拟器 LLM**（独立 system：求职者人设、可指定第 N 轮 emo 等），每轮根据 transcript 产 **下一条 user 句** → 写 broker 事件 → 等 `pa_outbound`/`pa_messages` → 拼 transcript。  
- 轮数/成本：`PA_LLM_CONVO_TURNS`、可 dry-run；CI 可只跑短对话或仅静态多轮 YAML（无第二 LLM）作便宜回归。  
- **产出：** `convo-*.md` 脱敏片段进 Report；可选每轮 `judge`。

**可选互补：** 单文件 YAML 多 `turns: []` 顺序注入（需 runner 支持或薄封装）。

## 7. 安全（Build 必须写进任务单的句子）

**OpenAI / Agents SDK：** **没有**「开箱即反 prompt injection」开关；**Moderation** 是独立 API、政策类，不等于防 jailbreak 指令。

**我们已有、且要当作产品主防线的是：**

- **工具：** `toolPolicy: allowlist` + `canUseConnector` + 每轮 `toolBudget`（`buildTurnTools` / `runConnector`）。  
- **记忆：** `filterMemoryWrite` / `isUnsafeMemoryContent`。  
- **输入/频控：** `checkPromptInjection`、`enforceRateLimit`（`packages/pa-safety`）；regex 有界，**金线** `eval-prompt-injection-in-fact-zh` + red-team 补充。

**本里程碑硬要求：**

- [ ] 在 **入站主路径**（`processInboundEvent` 前或首行，或 CF 包装层）调用 **`enforceRateLimit` + `checkPromptInjection`**；`allow: false` 时 **不**进入完整 agent turn，并 **`pa_audit_events` 记录**（种类与 Phase 23 `pa_abuse_events` 可渐进对齐）。  
- [ ] 文档/Report 中写明：主防线是 **allowlist+预算+入站门**，不是 system prompt 一句话。

详述与误区澄清见 [`.planning/v1.1-p10-northstar-security-channel.md`](./v1.1-p10-northstar-security-channel.md) §3。

## 8. 通道：Sendblue 与 macOS 同一套「大脑」

- **合流点唯一：** `pa_inbound_events` → **同一** orchestrator / **同一** `seed.json` 默认 agent → **`normalizeForIMessage`（orchestrator 出口）** → `pa_outbound`。  
- **仅 adapter 不同：**  
  - **入：** macOS 轮询/chat.db 行 idempotency；Sendblue webhook + `message_handle` + HMAC。  
  - **出：** worker 发本地；CF `onCreate(pa_outbound)` → `api.sendblue.co` REST。  
- **禁止：** Sendblue 侧再维护一套与 repo 中 default agent 分叉的「第二套大脑」；A/B 用 **特性开关** 于同一代码路径。  
- **回滚：** `PA_CHANNEL_LEGACY=1` 保留 macOS 权威、CF outbox 不抢发 — 以 [`21-PLAN`](./phases/21-sendblue-channel-migration/21-PLAN.md) 的 D-08 为准。

图见 [v1.1-p10-northstar-security-channel.md §4](./v1.1-p10-northstar-security-channel.md)。
