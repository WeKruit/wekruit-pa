# Phase 15.1 — Typing-indicator API verdict

Date: 2026-04-26
Author: P7

## Q1. `@photon-ai/imessage-kit` v3 (free tier) — typing-indicator method?

**No.** Inspected `node_modules/@photon-ai/imessage-kit/dist/index.d.ts`:
- No `setTyping`, `typing`, `isTyping`, or related export.
- Public surface: `IMessageSDK` with `send`, `getMessages`, `startWatching`, `close`. No typing indicator.

README states verbatim (line 19):
> Looking for advanced features like threaded replies, tapbacks, message
> editing, unsending, **live typing indicators**? Check out Advanced
> iMessage Kit and contact us at daniel@photon.codes.

Advanced iMessage Kit is paid/closed-source.

## Q2. AppleScript Messages dictionary — typing property?

**No.** `Messages.sdef` exposes only `send` (and a small set of properties on
`chat` such as `name`, `id`, `participants`). No `typing`, `is typing`,
`status`, or any property that maps to the user-visible typing indicator.
Photon's own AppleScript builder (dist/index.cjs ~lines 1613–1670) only
implements `send`.

## Q3. Non-chat.db, non-private-framework routes?

**No.** Reachable surface from a sandboxed Node process with Full Disk
Access only:
- AppleScript via `osascript` — limited to the Messages dictionary above.
- chat.db read — Phase 1 RED LINE: `readonly: true`. Cannot write.
- IMCore / private frameworks — would require Objective-C bridging and
  unsigned dylib loading, equivalent to a "paid Advanced kit" path and
  outside the free-tier scope.

## VERDICT: NONE

Path = chunked-message simulation (Phase 15.2a in PLAN).
