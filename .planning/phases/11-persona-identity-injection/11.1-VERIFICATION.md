# Phase 11.1 Verification — Persona Card Injection

## Summary

Deterministic persona card built from confirmed Firestore `MemoryFact`
rows is now injected into every default-LLM turn as a separate `system`
AgentInputItem at index 0, ahead of the Mem0 recall block. The card is
read-only orchestrator-side, never reaches the SDK as a tool, never
sourced from Mem0/Qdrant. Empty facts → no card injected (no bare
heading). Rollback flag `PA_PERSONA_CARD_DISABLED=true` skips the
injection without redeploy.

## Carry-overs (non-blocking, recorded for follow-up)

1. `OrchestratorStore.listMemoryFacts` returns
   `Promise<MemoryFact[] | { id: string; content: string }[]>` — a
   union for test-mock convenience. Cast `facts as MemoryFact[]` at
   the persona-build call site is defensive (builder filters on
   `status === "confirmed"`, lite-shape mocks discarded). Tighten to
   `Promise<MemoryFact[]>` after Phase 11.3.
2. `memoryBlockWithFacts` still owns dual responsibility (chat-
   completions fallback string AND default-path recall block). Option
   (b) refactor (split) deferred until the chat.completions fallback
   path is itself reviewed.
3. P9-B note for 11.3: `buildPersonaCard` is `userId`-keyed, NOT
   `mem0UserId`-keyed. When 11.3 lands, persona scope MUST stay
   `userId`-keyed; rescoping would silently follow Mem0 partition
   keys and violate A2/A3.
