# Phase 10.5 — Plan: Agents SDK Runtime Cutover (A3-NEW rewrite)

This is P8 execution material under the **A3-NEW architecture** locked by P10
on 2026-04-26 in `10.5-CONTEXT.md`. Decisions A1–A7 are not relitigated here;
read CONTEXT for the boundary table. The previous v1 plan
(`10.5-PLAN.v1-superseded.md`) targeted SiliconFlow `chat_completions` as the
default runtime — it is superseded. This rewrite targets:

- Default main turn = OpenAI `gpt-5.4-nano` via **Responses API** (A3).
- Hosted tools (`webSearchTool`) attached **directly to the Agent** (A4).
- Conversation history through SDK **`Session` interface** with a custom
  `FirestoreSession` (A7).
- SiliconFlow path is env-gated fallback only (`PA_AGENT_LLM_PROVIDER=siliconflow`).
- WeKruit-owned tools (`remember-fact`) stay routed through `runConnector`.

Repo: `wekruit-pa`. Live entry: `packages/pa-orchestrator/src/index.ts` →
`runAgentTurn` (`packages/agent-runtime/src/run.ts`).

## Architecture invariants this plan enforces

- `process.env.OPENAI_BASE_URL` is **never mutated** on the default OpenAI
  path. The default path passes an explicit `OpenAI` client into
  `setDefaultOpenAIClient`. SiliconFlow fallback may mutate env, but only
  inside a `try/finally` that restores the prior value.
- Mem0 LLM + embedder stay on SiliconFlow Qwen + bge-m3 (A5). Mem0 is
  recall-only; it is not a tool. The recall block is built per-turn by
  the orchestrator and prepended as a system input item.
- `__PA_RESET__` stays as a regex guard at the orchestrator. The LLM never
  has a `reset` tool (A6).
- All non-SDK tools (`remember-fact`, future `recall-memory`) ride the
  `runConnector` audit chain — `pa_tool_calls` + `pa_audit_events` —
  with the Phase 10 `policyReason: undefined` and audit-undefined filters
  preserved.

## T1 — Default runtime: OpenAI Responses API; SiliconFlow fallback isolated

### P8 Task Prompt

**Goal (WHY).** A1+A3-NEW: production main turns must run on OpenAI Agents
SDK against `api.openai.com` via Responses API with `gpt-5.4-nano`.

both wrong under A3-NEW. Phase 10 bug #3 proved that env mutation is the
root cause of cross-call baseURL poisoning (`/responses` → 404 on

**Inputs.**

- 10.5-CONTEXT A1, A3, A7. STATE.md known model gap (slug

**Scope.**

## T2 — `FirestoreSession implements Session`

### P8 Task Prompt

**Goal (WHY).** A7: conversation history flows through the SDK
`Session` interface so `run(agent, userMessage, { session })` auto-loads
and persists turns. The SDK never imports `firebase-admin` (A2 boundary).
Custom `FirestoreSession` adapts `pa_messages` Firestore reads/writes
into the SDK's `AgentInputItem[]` shape.

**Package decision.** `FirestoreSession` lives in **`@pa/agent-runtime`**,
NOT `@pa/memory`.

Rationale: `Session` is a runtime concern (defines what items the SDK
sees per turn). `@pa/agent-runtime` already imports `@openai/agents` and
already declares `AgentTurnContext`; it's the natural seam between
WeKruit-owned Firestore reads and SDK-owned input shape. `@pa/memory` is
about Mem0/Qdrant/persona facts (semantic empowerment), not transcript
plumbing — coupling Session to it would conflate two memory concepts P10
explicitly separated in A5/A7. The orchestrator already constructs a
`Firestore` instance per turn and passes it into `runAgentTurn` callers;
forwarding it into `FirestoreSession` is one extra constructor arg, not a
package-graph change. `@pa/memory` continues to own `loadRecentMessages`
and `loadPersonalizationContext` for the SF fallback path and for the
non-SDK code paths (memory commands list/forget/clear).

**Inputs.**
- `packages/agent-runtime/node_modules/@openai/agents-core/dist/memory/session.d.ts`
  (the 5-method interface — quoted in CONTEXT and again in this section
  for P8 convenience; verify against installed types before writing code).
- `packages/memory/src/stacked.ts` (`loadRecentMessages` — the canonical
  ordering query on `pa_messages` by `sessionId`, sorted ascending by
  `createdAt`. P8 reuses the same query shape.).
- `packages/core-types/src/index.ts` (`PA_COLLECTIONS.messages`,
  `ChatMessage`).
- `@openai/agents-core/dist/types.d.ts` (`AgentInputItem` shape — usually
  a discriminated union of role/content. Read installed `.d.ts` and
  match exactly).

**Scope.**
- New file `packages/agent-runtime/src/firestore-session.ts`:
  ```
  import type { Firestore } from "firebase-admin/firestore"
  import type { Session } from "@openai/agents"        // verify path
  import type { AgentInputItem } from "@openai/agents"  // verify path

  export type FirestoreSessionDeps = {
    db: Firestore
    sessionId: string
    /** Optional cap on items returned to the SDK (default 40). */
    historyLimit?: number
  }

  export class FirestoreSession implements Session {
    constructor(private readonly deps: FirestoreSessionDeps) {}

    async getSessionId(): Promise<string> { return this.deps.sessionId }

    async getItems(limit?: number): Promise<AgentInputItem[]> { … }

    async addItems(items: AgentInputItem[]): Promise<void> { … }

    async popItem(): Promise<AgentInputItem | undefined> { … }

    async clearSession(): Promise<void> { … }
  }
  ```
- `getItems(limit)`:
  - Query `db.collection(PA_COLLECTIONS.messages).where("sessionId","==",sessionId).limit(200).get()`.
  - Sort by `createdAt` ASC in memory (matches `loadRecentMessages`).
  - Slice tail by `limit ?? historyLimit ?? 40`.
  - Map each `ChatMessage` to an `AgentInputItem`. **Allowed mappings**:
    - `role === "user"` → `{ role: "user", content: [{ type: "input_text", text: body }] }`
      (or whichever shape the installed `AgentInputItem` requires; P8
      verifies against `.d.ts`).
    - `role === "assistant"` → analogous assistant shape.
    - `role === "system"` → drop. System persona is injected per-turn
      from `agent.systemPrompt`; we do not replay it from history.
    - Any other role (`"tool"`, future) → drop with a `log.warn` (do not
      throw — old rows must not break new turns).
  - Strip leading ISO timestamps if present (use existing
    `stripLeadingIsoTimestamp` exported from `@pa/agent-runtime`) so the
    LLM doesn't echo them.
- `addItems(items)`:
  - For each item, append a `ChatMessage` to `pa_messages` via
    `db.collection(PA_COLLECTIONS.messages).doc(<id>).set(...)`.
  - `id`: `randomUUID()` if the item has no stable id, else the SDK's id.
  - `createdAt`: `new Date().toISOString()`.
  - `idempotencyKey`: stable hash of `(sessionId, role, body, createdAt)`
    so retries don't double-write.
  - `rawMeta`: `{ source: "agents_sdk_session", role: <role>, sdkItemType: <type> }`.
  - **Filter `undefined` fields before `.set(...)`** (Phase 10 bug #2
    pattern) — Firestore rejects `undefined`. Use the same conditional
    spread pattern as `appendAuditEvent`.
  - Skip items the orchestrator already wrote in its own
    `appendMessage` call (the user inbound). Decision: gate on a
    `__pa_skip_session_write__` symbol on the item — orchestrator marks
    items it has already persisted via its own path; SDK-emitted
    items (assistant, tool) flow through `addItems` normally. **Open
    question for P8**: simpler alternative is to short-circuit
    `addItems` on idempotency-key collision and let the orchestrator
    retain control of user-row writes. P8 picks the simpler one and
    documents it inline.
- `popItem()`:
  - Read newest item by `createdAt` desc, limit 1. If none, return
    `undefined`. Else: mark deleted (soft) — write a tombstone field
    `popped: true, poppedAt: nowIso()` and merge-set. Return mapped item.
  - Rationale: `popItem` is rarely called by the SDK (used in human-loop
    flows). Soft delete preserves audit invariants. Document this
    behavior in a top-of-file comment.
- `clearSession()`:
  - Decision: **scoped soft delete**, not hard delete. Mark all messages
    in `sessionId` with `cleared: true, clearedAt: nowIso()`. Hard
    delete is a `__PA_RESET__` operation owned by the reset guard
    (A6) — SDK MUST NOT be able to wipe history.
  - Open the door for the SDK to call `clearSession` (e.g., on session
    rotation), but the user's confirmed memory facts and Mem0 vectors
    are untouched. Document in JSDoc.
- Export `FirestoreSession` from `packages/agent-runtime/src/index.ts`.

**Contract.**
- Implements all 5 `Session` methods. Type-check passes against installed
  `@openai/agents-core` `Session`.
- `getItems` returns items in **chronological order** (oldest first), per
  Session contract.
- `addItems` is idempotent on retry (same `idempotencyKey` → no-op).
- No `firestore-admin` direct import in `@openai/agents-core` (verify by
  grep: SDK should not appear in the import chain from
  `firestore-session.ts` to `@openai/agents-core`; only types flow that
  direction).
- Filters `undefined` before every `.set(...)`.

**Verification.**
- `npm run build --workspace=@pa/agent-runtime`.
- `npm test --workspace=@pa/agent-runtime` includes a NEW
  `firestore-session.test.ts` with a fake Firestore (the orchestrator
  test suite already has a fake Firestore pattern P8 can copy):
  - `getItems` returns an empty array for an empty session.
  - `getItems` returns 3 items in chronological order for a session with
    3 messages.
  - `getItems(limit=1)` returns only the most recent message.
  - `addItems` with 2 items writes 2 docs; second call with same items
    is a no-op (idempotency).
  - `popItem` on empty returns `undefined`; on non-empty returns the
    newest and tombstones it.
  - `clearSession` marks all docs `cleared: true` and does NOT delete.
  - Stale ISO-timestamp prefix is stripped from mapped item text.

**Red lines.**
- Do **not** import `firestore-admin` types from `@openai/agents-core`.
- Do **not** import `@openai/agents` runtime in this file — types only.
- Do **not** hard-delete documents from `clearSession` (A6 boundary).
- Do **not** include `system` rows in `getItems` output.
- Do **not** rely on Firestore composite indexes that don't exist
  today (`loadRecentMessages` uses `where + sort-in-memory` — keep
  that pattern).

**Goal-backward → Success criterion #4 (history through Session); also
unblocks #1 (default turn passes session into `run()`).**

## Rollout strategy

**Single-PR safe? No.** Three coupled invariants:

1. T1 (flip default to OpenAI Responses) without T8 (allowlist) means
   the LLM has no tools — "最近有啥电影" answered from stale model
   knowledge. Phase 10 boundary regression.
2. T5 (delete regex pre-router) without T4 + T8 means even a tooled
   LLM has nothing to satisfy current-info on production traffic
   between the deploys.
3. T2/T3 (Session) without T1 means we'd construct a Session against
   the chat_completions adapter, which doesn't honor it the same way.

**Recommended sequence (3 deploys, multi-commit branch).**

1. **Deploy 1 — runtime + Session + tools wired, no LLM exposure yet.**
   Land T1 + T2 + T3 + T6 + T7 + T9 + T10. Default agent still has
   `toolPolicy: "none"` (T8 unran), so:
   - LLM has no tools, no allowlist enforcement triggered.
   - Regex pre-router still fires (T5 unran), so live current-info
     keeps working via the legacy connector path.
   - The new default OpenAI Responses path runs end-to-end on live
     traffic but answers in plain text without tools — verify
     equivalent quality.
   - Run scenario suite + REST verify before proceeding.
2. **Deploy 2 — flip allowlist.**
   Run T8's migration script (`--apply`) in production. Now the LLM
   has tools attached, BUT the regex pre-router still short-circuits
   "最近有啥电影" before the LLM sees it. So tools are present but
   unreached. Verify nothing broke; sample
   `pa_turns.usage.hostedToolCalls` should still be empty/absent (no
   one is calling the tools because the regex bypasses the LLM).
3. **Deploy 3 — delete regex pre-router.**
   Land T5 + T11. Now LLM tool-choice is the only path. Run scenario
   suite, REST verify, fallback drill, write VERIFICATION.

Three deploys, each rollback-safe (set `toolPolicy: "none"` between
deploys 2 and 3 if the first inspection is suspicious; full revert
between deploys 1 and 2 is a single function redeploy with
`PA_AGENT_RUNTIME=chat_completions`).

**Kill switch.**
- **Primary**: `PA_AGENT_LLM_PROVIDER=siliconflow` env on
  `onPaInbound`. Engages SF fallback (chat_completions, no
  `webSearchTool`). Fast revert without code redeploy.
- **Secondary**: `PA_AGENT_RUNTIME=chat_completions` env. Falls all
  the way back to `runOpenAITurn`. Equivalent to pre-Phase-10
  behavior.
- **Tertiary**: `node scripts/pa-set-default-tool-policy.mjs
  --rollback --apply`. Removes tool exposure without changing the
  runtime. Useful if a specific connector misbehaves.

If schedule pressure forces a single PR, gate via
`PA_AGENT_LLM_PROVIDER=siliconflow` at deploy time, run migration,
then flip to `openai` in a second deploy. That collapses three to two
but introduces a deploy-time flag dance — not preferred.
