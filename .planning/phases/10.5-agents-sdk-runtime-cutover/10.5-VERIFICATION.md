# Phase 10.5 Verification — Agents SDK Runtime Cutover

## Summary

Default PA runtime migrated from `runOpenAITurn` (chat.completions on
SiliconFlow Qwen) to `runOpenAIAgentsTurn` (OpenAI Responses API on
`gpt-5.4-nano`). FirestoreSession owns transcript history through the
SDK Session interface. webSearchTool attached to default Agent under
allowlist policy. remember-fact connector replaces regex
`handleRememberCommand` write path. All regex pre-routers (current-info
boundary, remember branch) deleted. `__PA_RESET__` orchestrator guard
preserved. Mem0/Qdrant remains memory empowerment via SiliconFlow
Qwen + bge-m3 (unchanged). SiliconFlow demoted to env-gated fallback
(`PA_AGENT_LLM_PROVIDER=siliconflow`).

Three production-only bugs surfaced during first end-to-end run and
were fixed in `8fd2516`:

1. `firestore-session.chatMessageToInputItem` was passing UUID `id`
   through; OpenAI Responses API rejects ids that don't start with
   `msg_`. Stripped `id` so SDK manages it.
2. `orchestrator.appendMessage` short-circuited silently on
   idempotency-collision, losing `rawMeta.eventId`. Now merges
   `rawMeta` + `idempotencyKey` into the existing row when SDK
   already wrote it via `Session.addItems`.
3. Harness runner queried legacy `idempotencyKey == "out-${eventId}"`
   that no longer matches the hash-based key. Switched primary lookup
   to `rawMeta.eventId`; legacy lookup retained as fallback.

Also bumped scenario `turnTimeoutMs` from 30000 to 90000 — Responses
API + Session.getItems is slower than chat.completions baseline.

## Known carry-overs (non-blocking, recorded for follow-up)

1. `pa-connectors current-info calls Agents SDK hosted web_search and
   extracts citations` unit test fails at baseline `ddc616c` and
   continues to fail. Mock setup vs current SDK shape divergence.
   Production scenario passes; not a runtime regression.
2. `OrchestratorStore.runCurrentInfoConnector` and the legacy
   `current-info` connector are dead code on the default OpenAI path
   AND on the SiliconFlow fallback path (the SF fallback's
   `runOpenAIAgentsTurn` does not currently re-attach the legacy
   connector). If P10 considers SF fallback users asking "最近 X"
   getting raw model knowledge a regression, follow-up rewires
   `runCurrentInfoConnector` into `withSiliconFlowFallback`.

   **Update (Phase 10.5 cleanup, 2026-04-26):** accepted; SF fallback
   is degraded by design. P10 elected NOT to rewire the legacy
   connector into `withSiliconFlowFallback`. SF fallback users asking
   "最近 X" receive raw model-knowledge replies — this is reduced
   functionality on the kill-switch path, not a regression. The
   `runCurrentInfoConnector` store hook, the `current-info` connector
   registry entry, the `runOpenAIAgentsCurrentInfo` function, and the
   `CurrentInfoConnector{Input,Output}` types were removed from the
   codebase in the Phase 10.5 cleanup pass. The string identifier
   `"current-info"` is preserved in `agent.allowedConnectors` as the
   gate for SDK-hosted `webSearchTool` attachment, and as the
   `connectorName` value rewritten by `recordHostedToolCalls` for
   `pa_tool_calls` audit continuity.
3. `pa_tool_calls` deferred-audit row for hosted `web_search` calls
   is not currently being written for live web_search invocations,
   even though `webSearchTool` does fire (confirmed by the 8633
   input-token signature on the live turn). T9 logging extracts
   token usage correctly; the synthetic `recordHostedToolCalls`
   path for hosted tools needs investigation. Not blocking — main
   reasoning path is audited via `pa_turns.usage`.
4. Memory-write semantics shift: pre-T5 `"记住 X"` was deterministic
   via regex; post-T5 the LLM decides whether to call `remember-fact`.
   The `pa-safety.isUnsafeMemoryContent` gate stays inside the
   connector, but explicit-command UX may now feel less deterministic
   on borderline content.
5. `searchContextSize` defaults to `"medium"` per SDK. If cost
   monitoring reveals excessive web_search input-token spend, switch
   to `webSearchTool({ searchContextSize: "low" })`.
6. `seed.json` for `agent-registry` still ships
   `allowedConnectors: ["fake-echo"]`. Fresh installs diverge from
   production state.
