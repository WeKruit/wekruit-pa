# Phase 10.5 — Agents SDK Runtime Cutover

## Why this phase exists

Phase 10 closed the **letter** of "Agents SDK current-info connector" but
not the **spirit** of "PA runtime is OpenAI Agents SDK". Production main
turns still go through `runOpenAITurn` (chat.completions on SiliconFlow);
Agents SDK is wired only on the current-info side path. That fragmentation
plus the regex pre-routers in `pa-orchestrator/src/index.ts` is the root
cause of why we keep adding "intent classifier"-style hacks rather than
letting the LLM choose tools.

This phase pays the architectural debt before any Phase 11 persona work
lands. Building persona injection on a half-cut runtime would force a
second migration later.

## Locked architecture (P10, do not relitigate)

| ID | Decision | Boundary |
|---|---|---|
| A1 | **One agent runtime: OpenAI Agents SDK.** No parallel chat.completions path. `runOpenAITurn` is removed from the live orchestrator path; it can stay only as a deprecated test util. | All inbound message turns go through `runOpenAIAgentsTurn`. |
| A2 | **WeKruit-owned**: identity, canonical memory (Firestore + Mem0/Qdrant), outbound send policy, audit (`pa_tool_calls`, `pa_audit_events`). Agents SDK never reaches Firestore directly. | Unchanged from Phase 10 lock. |
| A3 | **Reasoning LLM is OpenAI `gpt-5.4-nano` via Responses API.** Agents SDK runs in default `responses` mode against `api.openai.com`. SiliconFlow no longer hosts the main turn. `setDefaultOpenAIClient` pins an OpenAI client; `setOpenAIAPI("responses")` is the default. (Note: `STATE.md` previously documented a probe failure with the wrong slug `gpt5.4nano` — correct slug is `gpt-5.4-nano`.) | The `runOpenAIAgentsTurn` adapter sends to `api.openai.com`. SiliconFlow path is kept only as an env-gated fallback (`PA_AGENT_LLM_PROVIDER=siliconflow`), not the default. |
| A4 | **Hosted tools (web_search, file_search, etc.) become first-class SDK tools, not hand-built connectors.** Because main turn is now on the Responses API, the SDK can attach `webSearchTool({})` directly to the `Agent`. The current-info connector boundary collapses: orchestrator no longer needs an isolated `OpenAIProvider` for it. Other WeKruit-owned tools (`remember-fact`, future `recall-memory`) remain custom connectors routed through `runConnector` for audit/safety. | The Phase 10 isolated-baseURL hack in `current-info.ts` is removed. Audit/policy still run for non-SDK tools through the connector layer. |
| A5 | **Mem0/Qdrant stays as memory empowerment.** Mem0 LLM + embedder still run against SiliconFlow Qwen + bge-m3 (cost-optimized for the embedding pipeline; switching Mem0 to OpenAI is a separate decision). The Mem0 recall block is injected into the Agents SDK turn — see A7. | Mem0 env (SILICONFLOW_API_KEY for Mem0 LLM, MEM0_EMBED_MODEL bge-m3) unchanged. |
| A6 | **`__PA_RESET__` stays as orchestrator-level guard, not a tool.** It must be 100% deterministic; the LLM does not get to decide whether to wipe a user's memory. | Only the regex pre-routers for "memory recall" / "current-info" / "remember" intents get deleted. The reset guard stays. |
| A7 | **Conversation history uses SDK `Session` interface; backed by Firestore.** A custom `FirestoreSession implements Session` reads/writes `pa_messages` so `run(agent, userMessage, { session })` auto-loads + persists turns. Mem0 semantic recall is a separate channel: a per-turn `system` input item built by the orchestrator from `mem0Search` + confirmed Firestore facts, prepended to the user message. The SDK never imports `firebase-admin`; it only sees the `Session` interface. | Replaces the legacy `loadRecentMessages` + `toOpenAIMessages` history splice. `pa_messages` schema unchanged; `Session.getItems(limit)` maps to existing `sessionId` ordered fetch. |

## Pre-LLM regex routers to remove

These currently bypass the LLM by classifying intent via regex. They will
be replaced by tool calls the LLM chooses on its own.

- `buildCurrentInfoBoundaryReply` (orchestrator/index.ts) — replaced by
  the LLM choosing the `current-info` tool when needed.
- `handleRememberCommand` — replaced by a `remember-fact` connector the
  LLM calls when a user asks PA to remember something.

## Pre-LLM regex guards to keep

- `maybeHandleResetCommand` (`__PA_RESET__`). System-only.
- Harness `suppressOutbound` flag on broker events.

## Connector surface (what the LLM gets to choose from)

Default agent transitions from `toolPolicy: "none"` → `toolPolicy: "allowlist"`,
with `allowedConnectors` covering at minimum:

- `current-info` — existing, OpenAI-hosted web_search behind connector.
- `remember-fact` — new. Writes to `pa_memory_facts`. Replaces
  `handleRememberCommand`.
- `recall-memory` — optional, future. The Mem0 recall block is already
  injected, so this is only needed when the LLM wants to do an explicit
  second-pass query.

Phase 10.5 ships `current-info` (already live) and `remember-fact`. Other
connectors stay backlog.

## Production constraints carried over from Phase 10 closure

- `OPENAI_BASE_URL` env was previously owned by SiliconFlow chat_completions.
  Under A3-NEW the main turn no longer relies on this env for the default
  path; SiliconFlow path becomes opt-in. Mem0 still uses
  `MEM0_LLM_BASE_URL` pinned to SiliconFlow.
- `appendAuditEvent` and `runConnector` already filter `undefined` fields
  to avoid Firestore rejection. Any new connector must follow that pattern.
- Harness scenarios must keep `suppressOutbound: true`. Adding new
  connector tool calls cannot bypass that.

## New secrets / env baseline

- `PA_OPENAI_AGENT_API_KEY` (already bound in Phase 10) becomes the main
  turn key. Same secret, expanded role.
- `PA_AGENT_MODEL` defaults to `gpt-5.4-nano`. Override via env per agent
  record stays via `agent.model`.
- `PA_AGENT_LLM_PROVIDER=openai` (default) | `siliconflow` (fallback).
- `SILICONFLOW_API_KEY` retained for Mem0 LLM/embedder; not consumed by
  the default agent turn anymore.

## Success criteria (goal-backward)

1. Default agent runs on Agents SDK + OpenAI `gpt-5.4-nano` via Responses
   API in production. `runOpenAITurn` no longer fires for inbound user
   messages.
2. `current-info` is satisfied by SDK-attached `webSearchTool` chosen by
   the model. Phase 10's standalone `current-info` connector is either
   removed or kept only as legacy fallback for the SiliconFlow opt-in
   path. Regex pre-router deleted.
3. `remember-fact` connector exists; "记得我喜欢..." pattern is no longer
   regex-handled in the orchestrator.
4. Conversation history flows through `FirestoreSession implements Session`;
   Mem0 recall block is injected as a per-turn system input item built by
   the orchestrator. Existing `pa_messages` rows still appear in dashboard
   transcript.
5. `__PA_RESET__` still works exactly as before; harness scenario passes.
6. Full scenario suite passes: memory recall (zh/en/ja/mixed), reset,
   current-info live. Harness `pa_outbound = 0`.
7. Production smoke: real inbound with "最近有啥电影" returns sourced
   2026-04-26 web answer via SDK web_search; "记得我喜欢XXX" persists to
   `pa_memory_facts` without dedicated regex.
8. Cost monitoring: per-turn token usage logged and surfaced in
   `pa_tool_calls` or a new `pa_turns.usage` field so the OpenAI vs
   SiliconFlow cost comparison is data-driven, not hand-waved.

## Out of scope (do not creep)
