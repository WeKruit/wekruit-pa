## Feature Flag Infra 设计 (Phase 24.5 拍板)

| 维度 | 决断 | 拒绝方案 + 理由 |
|---|---|---|
| **存哪** | Firestore `pa_feature_flags/{key}` collection | env-var 不能秒级回滚; Remote Config 增加依赖面 |
| **缓存** | CF 进程内 30s TTL 内存缓存 | 无缓存 = N 次/turn Firestore read; 5min TTL kill switch 等不起 |
| **颗粒度** | 三层 = `global` / `perEnv` / `perUser` (allowlist[] / blocklist[]) | 测试号绕开 rate-limit 硬需求 |
| **API** | `getFlag(key: string, ctx: { userId?, env? }): Promise<FlagValue>` | 单一入口, 业务代码不感知存储 |
| **审计** | dashboard CRUD → `pa_audit_events` (actor / key / oldVal / newVal / reason). 读取**不写** audit | |
| **回滚** | dashboard "Revert to previous" = 读 audit 上一条 → 写回. ≤30s 全网生效 | |
| **schema** | `{ key, value, type: bool\|string\|number\|json, scope, allowlist[], blocklist[], updatedAt, updatedBy, reason, version }` | |
| **首批 flag (24.5 落地初始化)** | `PA_CHANNEL_LEGACY` / `PA_PROACTIVE_DISABLED` / `PA_VOICE_MIRROR_DISABLED` / `paRateLimitPerUserEnabled` / `selfEvolveEnabled` / `voiceEvalAutoRerun` | 收编现存 env-var 散点 |

**24.5 success criteria**:
1. `getFlag()` SDK 在 CF + dashboard-web 双端可用
2. Dashboard `/admin/flags` page list / edit / revert / audit history
3. 现存 4 个 env-var 迁移到 flag (env 保留作 emergency override)
4. 30s TTL 缓存命中率 ≥ 95%
5. 测试号 perUser bypass rate-limit 验证通过

## 关键决策 (P10 拍板)
